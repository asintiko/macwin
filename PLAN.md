# План MacWin 0.2: окно приложения, роли и расстановка экранов

Следующая версия: [PLAN-0.3.md](PLAN-0.3.md) — исправление курсора, скорость, отзывчивость, несколько устройств и Linux (Kali).

Статус каждого этапа ведётся в GitHub: эпик [#10](https://github.com/asintiko/macwin/issues/10) и отдельный issue на этап. Обозначения: ✅ готово, 🔄 в работе, ⬜ не начато, 🧪 нужна проверка на реальных компьютерах.

## Цель

MacBook — **основной** компьютер. К нему подключены два монитора: большой сверху и ещё один сбоку. Windows-ноутбук — **вторичный**, стоит слева от MacBook, под большим монитором. Курсор MacBook уходит за левый край MacBook и продолжает движение на Windows, как при Universal Control с iPad. Клавиатура, копирование и вставка, передача файлов общие.

Первый запуск:

1. На MacBook открываем MacWin и выбираем «Этот компьютер — **основной**».
2. Видим текущую расстановку мониторов MacBook (как в «Настройки → Мониторы») и перетаскиваем Windows-ноутбук туда, где он стоит.
3. На Windows открываем MacWin и выбираем «**Вторичный**» — появляется код `123-456`.
4. Вводим код на MacBook — компьютеры связаны. Повторно ничего настраивать не нужно.

## Что уже есть (фазы 0–3) ✅

- Ядро, протокол, QUIC с взаимным TLS и закреплением сертификатов; захват и внедрение ввода на macOS и Windows.
- Сопряжение по одноразовому коду (SPAKE2), ключи в Keychain/DPAPI, `config.toml`.
- Общая клавиатура и мышь через край экрана, аварийная комбинация, перехват управления локальным вводом.
- Общий буфер: текст, картинки, файлы и папки; плавная прокрутка.
- Поиск в локальной сети, переподключение, меню в строке меню/трее, автозапуск, DMG и Windows EXE/ZIP, CI на трёх ОС.
- 🧪 Живой сеанс на двух компьютерах ещё не проводился (этап 8).

Ограничение, которое снимает этот план: партнёр может стоять только «слева» или «справа» от всего рабочего стола, обе машины настраиваются отдельно, а всё управление — в меню трея.

## Решения

**Роли.** `role = "primary" | "secondary"` в `config.toml`. Вторичный показывает код и ждёт; основной вводит код, подключается и хранит расстановку. Управлять можно с обеих сторон: тачпад Windows тоже может перевести курсор на Mac через тот же общий край.

**Расстановка.** Экран партнёра пристыкован к конкретному монитору основного: `монитор + сторона (слева/справа/сверху/снизу) + смещение` в логических единицах (пункты macOS, DIP Windows). Такая привязка переживает смену размеров экрана партнёра и перестановку остальных мониторов. Курсор переходит только там, где экраны действительно соприкасаются; в углу сторона выбирается по направлению движения. Старый `side = left/right` превращается в привязку к крайнему монитору по центру.

**Протокол.** Основной добавляет привязку в `Hello` новым необязательным полем; старые версии его пропускают. Вторичный по тем же данным строит зеркальную раскладку. Изменение расстановки перезапускает сеанс (около секунды).

**Окно.** Новый крейт `macwin-ui` на egui/eframe 0.37 с OpenGL (glow): кроссплатформенный, лицензии MIT/Apache, кроме шрифтов egui (OFL-1.1 и Ubuntu Font License — разрешены исключением в `deny.toml`). Один процесс: окно на главном потоке; трей macOS устанавливается в цикл событий winit, трей Windows работает в своём потоке. Закрытие окна оставляет MacWin в фоне. При автозапуске окно не открывается.

## Риски

- Окно, трей, Dock и Cmd+Q на macOS и Windows проверяются в CI только сборкой и тестами; поведение на экране — на этапе 8.
- glow требует OpenGL: на Windows без драйвера видеокарты (виртуальные машины) окно может не открыться. Запасной вариант — wgpu.
- Windows со смешанным масштабом мониторов (например, 150 % и 100 %) переводится в логические единицы одним коэффициентом; возможна неточность на стыке.
- Мониторы, подключённые на лету, учитываются при следующем подключении (бэклог #9).
