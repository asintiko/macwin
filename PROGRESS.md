# Прогресс MacWin

Обновлено: **19 октября 2026**.

Цель — один набор клавиатуры, мыши и буфера обмена для MacBook и Windows-ноутбука
в одной сети. Версия **0.2** превращает MacWin из меню в трее в обычное приложение
с окном: выбор ролей «основной / вторичный», расстановка экранов перетаскиванием и
сопряжение вводом кода. План и статус этапов — в [PLAN.md](PLAN.md).

Работа над 0.3 ведётся в ветке `hoplite/lampsakos-404c89c1` репозитория
`efajkkjegfjk/macwin` (продолжение `hoplite/emporion-50969eff`), план — в
[PLAN-0.3.md](PLAN-0.3.md). Тестовые сборки 0.2 — в
[последнем выпуске](https://github.com/djjdjdkdjdvdvd/macwin/releases/latest);
установка — в [README](README.md#installing) и [FIRST_RUN.md](FIRST_RUN.md).

## Готовность

Этапы 1–7 плана из 8 сделаны и проходят CI на Linux, macOS и Windows; выпуск
публикуется автоматически. Не сделан только этап 8 — проверка на настоящих

окна) сохранена отдельными коммитами.

## Сделано в версии 0.2

**Окно и сценарий** (этапы 3–5). Мастер первого запуска: «Каким будет этот
компьютер?» → у основного — расстановка и ввод кода, у вторичного — крупный код и
ожидание. Главное окно: статус и пауза, вкладки «Расстановка», «Буфер обмена»,
«Настройки» (автозапуск, Cmd↔Ctrl, поиск в сети, язык, разрешения macOS),
«О программе»; отвязать партнёра, сменить роль, настроить заново. Русский и
английский.

**Роли и сопряжение** (этап 2). Вторичный показывает код и слушает; основной
вводит код (или адрес вручную), подключается и хранит расстановку. После ввода
кода оба сразу переходят в «Подключено», без вопроса о стороне. Вторичный
получает расстановку основного в каждом `Hello` и показывает её.

**Расстановка** (этапы 1 и 4). Экран партнёра пристыкован к конкретному монитору
основного с любой стороны и со смещением; курсор переходит только там, где экраны
соприкасаются. Редактор показывает мониторы этого компьютера, а после подключения —
реальные экраны партнёра; изменение применяется без перезапуска приложения.

**Один процесс, трей, Dock, автозапуск** (этап 6). Окно на главном потоке; значок
в строке меню macOS живёт в его цикле событий, значок в трее Windows — в своём
потоке. Закрытие окна оставляет MacWin в фоне; меню значка: статус, «Открыть
MacWin», пауза, выход. На macOS значок в Dock виден, пока открыто окно; повторный
запуск из Finder/Dock показывает окно. На Windows щелчок по значку или повторный
запуск показывает окно уже работающей копии. Автозапуск при входе —
`--background`: без окна, только значок; запись автозапуска от 0.1 (без
`--background`) при первом запуске 0.2 обновляется сама, а записи других копий
не трогаются. Если OpenGL недоступен, остаётся прежнее меню трея.

**Разрешения macOS.** При обычном запуске (не автозапуске) MacWin сам вызывает
системные запросы «Универсальный доступ» и «Мониторинг ввода»: без этого macOS не
показывает приложение в списках Системных настроек и его пришлось бы добавлять
кнопкой «+». Окно показывает состояние разрешений (проверка каждые 2 с) и
открывает нужный раздел настроек; общий доступ возобновляется сам, когда
разрешения выданы. `macwin run` (режим командной строки) тоже учитывает роль и
расстановку.

**Сборка и установка** (этап 7).
- macOS: одна команда в Терминале (`install-macos.sh`) скачивает DMG через `curl`
  (без карантина — Gatekeeper не спрашивает), закрывает запущенный MacWin
  (команда «Выйти», затем SIGINT, принудительно — только в крайнем случае),
  ставит приложение в «Программы» (`~/Applications`, если нет прав на
  `/Applications`), подписывает тестовую сборку для этого Mac и сбрасывает
  устаревшие разрешения, если подпись изменилась (иначе macOS показывает их
  включёнными, но они не работают). Тот же скрипт — `Install MacWin.command`
  внутри DMG. Проверяет macOS 15+ и Apple Silicon (в том числе в Терминале под
  Rosetta).
- Подпись Developer ID и нотаризация готовы: при секретах `MACOS_CERTIFICATE_P12`,
  `MACOS_CERTIFICATE_PASSWORD`, `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_PASSWORD`
  CI подписывает с Hardened Runtime, нотаризует и степлит DMG — тогда его можно
  просто перетащить в «Программы» без предупреждений. Без секретов сборка
  остаётся тестовой (ad-hoc).
- Windows: `install-windows.ps1` (`irm … | iex`) скачивает ZIP без пометки
  «из интернета» (SmartScreen не мешает), сверяет SHA-256 и запускает
  установщик: «Пуск», автозапуск в фоне, брандмауэр, окно после установки.
  Есть и отдельный EXE без установки.
- Тег `v*` публикует выпуск из проверенных CI-пакетов с постоянными именами
  файлов, поэтому ссылки `releases/latest/download/…` не устаревают.
- `THIRD_PARTY_NOTICES` в обоих пакетах содержит лицензии шрифтов, которые
  egui встраивает в окно (Ubuntu Font Licence 1.0, Hack — MIT и Bitstream Vera,
  иконки — MIT).
- Версия 0.2.0.

## Ограничения

- Окно, трей, Dock, Cmd+Q, автозапуск, разрешения и настоящий сеанс на двух
  компьютерах в CI проверяются только сборкой и тестами; на экране — на
  [этапе 8](https://github.com/asintiko/macwin/issues/8) по [FIRST_RUN.md](FIRST_RUN.md).
- Без сертификата Developer ID DMG не нотаризован: устанавливайте командой из
  Терминала. После каждого обновления тестовой сборки macOS заново спрашивает
  разрешения и один раз — доступ к связке ключей («Всегда разрешать»); подпись
  Developer ID это убирает. Windows-программы не подписаны.
- DMG только для Apple Silicon и macOS 15+, Windows — только x64.
- Откат на 0.1 не прочитает `config.toml`, сохранённый 0.2 (новые ключи `role`,
  `language` и `[arrangement]`): удалите их или файл целиком.
- Экран входа, блокировка и UAC Windows не поддерживаются (проект службы —
  `.agents/tasks/phase4-design.md`). Мониторы, подключённые на лету, учитываются
  при следующем подключении.

## Аудит стабильности: 20 октября 2026

### A.1 — инжекция и завершение сессии

- Нативный инжектор работает на отдельном потоке с ограниченной FIFO-очередью,
  без мьютекса Core: синхронный callback системного hook больше не ждёт этот
  мьютекс из вызова инжекции. Переполнение, ошибка или паника завершают сессию.
- Поток учитывает фактически отправленные нажатия и пытается отпустить их
  при остановке, включая частично применённую ошибочную команду. Завершение
  сессии ждёт остановки старых потоков перед переподключением.
- Замер приёма включает ожидание очереди и сам нативный вызов.
- Проверено на Linux: `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`,
  `cargo test --workspace --all-features --locked`,
  `cargo run -p keymap-gen --locked -- --check`.
  Новые тесты проверяют FIFO, перегрузку, снятие нажатий после ошибки/паники
  и callback захвата, вызванный во время инжекции.
- Поведение реальных macOS/Windows hooks и невозможность системного вызова
  зависнуть внутри ОС здесь не проверены; аппаратные замеры остаются открыты.

### A.2 — остановка и повтор чтения clipboard

- Отправка событий больше не блокирует clipboard worker: при заполненной
  очереди сохраняется последнее ожидающее изменение. Остановка обрабатывается
  без ожидания чтения очереди; успешная запись от peer отменяет устаревшее событие.
- После временной ошибки snapshot счётчик не помечается обработанным:
  следующее чтение повторяется даже без нового изменения clipboard.
- Проверено на Linux: `cargo test -p macwin-agent --lib --locked clipboard::tests`
  — 7 тестов, включая заполненную очередь, остановку и повтор snapshot;
  форматирование и `git diff --check` целевых файлов.
- Реальная занятость Windows clipboard и системный буфер macOS требуют
  проверки на устройствах; fake-backend подтверждает только логику worker.

### A.3 — ограниченный обход передаваемых файлов

- Обычные файлы и каталоги собираются только в пределах оставшегося лимита
  манифеста; обход прекращается на первой лишней записи, до сортировки.
  Symlinks и специальные файлы по-прежнему не передаются и не занимают лимит.
- Сохранены сортировка, ограничения глубины, размера и имён; файлы и каталоги
  по-прежнему учитываются в общем числе записей.
- Проверено на Linux: `cargo test -p macwin-agent --lib --locked transfer::tests`
  — 12 тестов. Новые тесты проверяют точную границу манифеста и число прочитанных
  элементов iterator: при лимите 1 чтение прекращается на втором из четырёх.
  Форматирование и `git diff --check` целевых файлов прошли.

### A.7 — переполнение длины frame

- Десятый байт длины проверяется до сдвига: допустимы только 0 и 1, без
  продолжения varint. Переполнение больше не превращается в пустой frame;
  незавершённый десятый байт отклоняется сразу, без ожидания одиннадцатого.
- Сохранена поддержка допустимого неканонического нуля из десяти байтов.
- Регрессионный тест сначала воспроизвёл ошибку на прежнем коде; после
  исправления `cargo test -p macwin-proto --locked` прошёл: 35 unit-тестов
  и 7 golden-тестов. Форматирование и `git diff --check` прошли.

### A.4 — завершение обязательных потоков QUIC

- EOF/reset control или input закрывает link, даже если peer оставил QUIC
  открытым. Усечённый frame отклоняется сразу; чистый FIN допускает 750 мс
  на штатное закрытие соединения после flush.
- Loopback-тесты проверяют FIN, reset, неполный frame, единственный `Closed`
  и завершение receive-очереди. Отмена отдельной передачи файлов не закрывает
  рабочий control-link; политика одноразовых clipboard-потоков не изменена.
- Проверено на Linux: `cargo test -p macwin-net --locked` — 25 unit и
  19 loopback-тестов; строгий Clippy всех targets/features `macwin-net`,
  форматирование и `git diff --check` прошли.

### A.10 — длина заголовка файлового потока

- Отдельный от frame-декодера `read_len` отклоняет переполнение и продолжение
  varint в десятом байте до сдвига. Большая длина больше не превращается
  в маленькую; некорректный файловый поток не передаётся драйверу.
- Проверены допустимые значения до `u64::MAX`, неканонический ноль,
  сохранность следующего за префиксом байта, переполнение, продолжение и EOF.
- На Linux прошли 28 unit и 19 loopback-тестов `macwin-net`, строгий Clippy,
  форматирование и `git diff --check`. В `files_header_from_wire` отдельная
  ошибка суммирования не подтвердилась: там уже используется `checked_add`.

### A.8 — CLI и активная сессия

- `unpair` и `config set` удерживают существующий instance lock на весь
  read-modify-write. При активном tray/run команды отказывают, не меняя
  сохранённый конфиг, и предлагают сначала остановить MacWin.
- Два целевых теста на Linux проверяют отказ без изменения конфига,
  владение lock внутри операции и успешную запись после освобождения lock.
  Форматирование и `git diff --check` прошли. Нативная tray-сессия на
  macOS/Windows в этой среде не проверялась.

### A.9 — сторона в классическом tray-меню

- Legacy Left/Right скрыты, если сторона не влияет на placement: у Secondary
  или у Primary с явной arrangement. Контроллер игнорирует устаревшие клики
  и повторно проверяет актуальный конфиг перед изменением.
- На Linux прошли 6 lifecycle-тестов (включая A.8), 6 tray integration-тестов,
  форматирование и `git diff --check`. Проверены доступность, состояние меню,
  эффективная placement и отсутствие записи при устаревшем действии.
- Внешний вид и клики в нативном tray macOS/Windows остаются непроверенными;
  headless-тесты не заменяют эту проверку.

### A.6 — удерживаемые клавиши и синтетические сочетания

- Fn/gesture chord повторно нажимает удерживаемую основную клавишу, чтобы
  сочетание сработало, но не отправляет синтетический key-up. Освобождение
  остаётся за физическим отпусканием. Удерживаемые модификаторы не трогаются.
- Учтён возврат на свой экран и повторный вход с удерживаемой клавишей;
  клавиши, нажатые локально до перехода, сохраняют прежнюю `pre_grab` семантику.
- Входящий Enter отклоняется, пока в Idle удерживается локальная клавиша
  или кнопка: её последующее отпускание не теряет локального владельца.
- На Linux прошли 157 тестов `macwin-core`, строгий Clippy, форматирование
  и `git diff --check`. Два Engine в тестах проверяют состояние на peer,
  но Fn, жесты и системные key events на реальных Mac/Windows ещё не проверены.
